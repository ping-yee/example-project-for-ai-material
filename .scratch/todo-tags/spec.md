# Todo List 標籤功能規格

Status: ready-for-agent

## Problem Statement

目前 Todo List 只能利用任務的狀態、優先級、日期和標題整理內容。當任務數量增加時，使用者無法用自己熟悉的主題、情境或專案名稱標記任務，也無法快速找出具有相同意義的任務。固定且互斥的分類不足以表達一項任務同時屬於多個面向，因此需要可重複使用、可複選的標籤。

## Solution

讓使用者在新增或編輯任務時，從全站共用的標籤中選取最多 10 個，也能在任務表單內建立新標籤。任務成功儲存時，新標籤與任務關聯必須一起成功；驗證失敗時則全部不寫入。

任務卡片會以 chip 顯示標籤，沒有標籤時顯示「未加標籤」。使用者可點擊 chip，以單一標籤或「未加標籤」篩選任務。標籤篩選與關鍵字搜尋及一般篩選互斥，但不會清除排序條件。

## User Stories

1. 身為 Todo List 使用者，我想替任務加上標籤，以便依自己的工作方式整理任務。
2. 身為 Todo List 使用者，我想讓同一項任務具有多個標籤，以便表達任務同時具有多種意義。
3. 身為 Todo List 使用者，我想在建立任務時選取既有標籤，以便重複使用一致的標記。
4. 身為 Todo List 使用者，我想在編輯任務時看到目前已套用的標籤，以便理解任務目前如何被整理。
5. 身為 Todo List 使用者，我想在編輯任務時加入既有標籤，以便更新任務的整理方式。
6. 身為 Todo List 使用者，我想在編輯任務時移除標籤，以便修正不再適用的標記。
7. 身為 Todo List 使用者，我想讓未被選取的既有標籤保持不變，以免局部更新任務狀態時意外改動標籤。
8. 身為 Todo List 使用者，我想讓一項任務最多套用 10 個標籤，以便介面保持可讀且標籤仍具有辨識價值。
9. 身為 Todo List 使用者，我想在沒有合適標籤時選擇「新增標籤」，以便直接在任務流程中建立所需標籤。
10. 身為 Todo List 使用者，我想在選擇「新增標籤」後輸入名稱，以便清楚知道自己正在建立新標籤。
11. 身為 Todo List 使用者，我想讓新標籤在任務成功儲存時才建立，以免取消表單後留下無意義的標籤。
12. 身為 Todo List 使用者，我想讓成功建立的新標籤自動套用到目前任務，以免建立後還要再次選取。
13. 身為 Todo List 使用者，我想讓標籤名稱自動移除頭尾空白，以免視覺相同的名稱被誤認為不同標籤。
14. 身為 Todo List 使用者，我想收到空白標籤名稱的驗證錯誤，以免建立沒有辨識意義的標籤。
15. 身為 Todo List 使用者，我想讓標籤名稱最多為 50 個字元，以免過長名稱破壞選單及任務卡片版面。
16. 身為 Todo List 使用者，我想使用中文、英文、數字、內部空格及 emoji 命名標籤，以便使用自然且有意義的名稱。
17. 身為 Todo List 使用者，我想讓標籤名稱不分大小寫地保持唯一，以免出現只有大小寫不同的重複標籤。
18. 身為 Todo List 使用者，我想在輸入已存在的標籤名稱時看到「標籤已存在，請從選項中選取」，以便知道應改選既有標籤。
19. 身為 Todo List 使用者，我想讓重複名稱錯誤不自動套用既有標籤，以免系統在我未確認時改變任務。
20. 身為 Todo List 使用者，我想在標籤驗證失敗時保留任務表單內容，以便修正錯誤而不用重新輸入。
21. 身為 Todo List 使用者，我想讓任務與新標籤一起成功或一起失敗，以免任務和標籤處於不一致狀態。
22. 身為 Todo List 使用者，我想在標籤選項中搜尋既有標籤，以便標籤增加後仍能快速找到需要的項目。
23. 身為 Todo List 使用者，我想讓既有標籤依名稱排序，以便選項順序穩定且容易掃描。
24. 身為 Todo List 使用者，我想讓「新增標籤」固定出現在選項頂端，以便隨時能找到建立入口。
25. 身為 Todo List 使用者，我想讓任務卡片以 chip 顯示所有標籤，以便快速辨識任務的標記。
26. 身為 Todo List 使用者，我想讓多個 chip 自動換行，以便任務卡片在不同螢幕寬度下仍可閱讀。
27. 身為 Todo List 使用者，我想讓沒有標籤的任務顯示灰色「未加標籤」chip，以便區分尚未整理的任務。
28. 身為 Todo List 使用者，我想點擊任務卡片上的標籤 chip，以便直接查看具有該標籤的任務。
29. 身為 Todo List 使用者，我想點擊「未加標籤」chip，以便找出所有尚未加上標籤的任務。
30. 身為 Todo List 使用者，我想一次只選擇一個標籤進行篩選，以便清楚理解目前的結果集合。
31. 身為 Todo List 使用者，我想選擇「全部」，以便離開標籤篩選並重新查看所有任務。
32. 身為 Todo List 使用者，我想在啟用標籤篩選時清除搜尋關鍵字與一般篩選條件，以免不同篩選模式產生難以理解的交集。
33. 身為 Todo List 使用者，我想在啟用搜尋或一般篩選時清除標籤篩選，以便畫面永遠只有一種篩選模式生效。
34. 身為 Todo List 使用者，我想在切換篩選模式時保留排序條件，以便結果仍依我選擇的順序顯示。
35. 身為 Todo List 使用者，我想清楚看到目前使用中的篩選模式，以便理解畫面為何只顯示部分任務。
36. 身為 Todo List 使用者，我想讓原有狀態、優先級與日期條件仍可彼此組合，以免新增標籤功能破壞既有能力。
37. 身為 Todo List 使用者，我想讓標籤篩選結果仍能依建立時間、更新時間、標題、優先級、狀態或截止日期排序，以便延續現有整理方式。
38. 身為 Todo List 使用者，我想讓既有任務在功能上線後維持「未加標籤」，以免資料遷移自行猜測標籤。
39. 身為 Todo List 使用者，我想讓新任務可以不選任何標籤，以便標籤保持選填。
40. 身為 Todo List 使用者，我想讓已無任務使用的標籤繼續出現在選項中，以免系統未經允許自動刪除我的標籤。
41. 身為 Todo List 使用者，我想在刪除任務後保留其標籤，以便其他任務或未來任務繼續使用。
42. 身為 Todo List 使用者，我想讓標籤在任務清單、搜尋結果及一般篩選結果中一致呈現，以免切換模式時遺失必要資訊。
43. 身為 Todo List 使用者，我想讓完成、重新開啟及刪除任務等既有操作繼續正常運作，以免標籤功能造成回歸。
44. 身為 Todo List 使用者，我想讓全站使用同一套標籤，以符合目前沒有登入及個人資料隔離的產品模式。

## Implementation Decisions

- 使用領域 glossary 中的正式詞彙：`Task` 對應「任務」、`Tag` 對應「標籤」、`Untagged` 對應「未加標籤」；不得在介面或規格中改稱「分類」。
- 任務與標籤是多對多關係。標籤獨立保存，任務與標籤的關聯不得重複。
- 新增標籤儲存經頭尾空白清理後的顯示名稱，並以不分大小寫的正規化鍵建立資料庫唯一限制；應以資料庫限制防止併發請求建立重複標籤。
- 既有任務不需回填標籤資料；沒有任何標籤關聯即代表「未加標籤」，而不是建立一筆名為「未加標籤」的標籤。
- 標籤為全站共用，不與使用者或帳號建立所有權關係。
- 任務寫入 interface 同時接受既有標籤識別資訊與待建立的新標籤名稱，合計最多 10 個。請求未提供標籤資料時，局部任務更新必須保留既有標籤。
- 新增任務時，提交的標籤集合就是任務建立後的完整集合。編輯任務時，明確提交標籤集合代表以該集合同步關聯，因此可加入或移除標籤。
- 建立或更新任務、新增標籤及同步關聯必須放在同一筆資料庫交易中。任何任務或標籤驗證錯誤都要回滾整筆操作。
- 新標籤名稱禁止為空，最多 50 個字元，允許中文、英文、數字、內部空格及 emoji。計算長度時應以使用者可理解的字元長度為準，而不是原始位元組數。
- 新標籤名稱正規化後若已存在，回傳欄位層級驗證錯誤「標籤已存在，請從選項中選取」；不得自動改成既有標籤。
- 任務讀取 interface 的每筆任務都必須包含其標籤集合，讓完整清單、搜尋、一般篩選及標籤篩選使用一致的回應形狀。
- 標籤選項 interface 回傳全站標籤，依顯示名稱排序，並支援依名稱搜尋。它不負責建立、重新命名或刪除標籤。
- 刪除任務只移除任務及其標籤關聯，不得刪除標籤。從任務移除最後一個關聯時，標籤也必須保留。
- 標籤篩選 interface 一次只接受一個既有標籤或特殊的「未加標籤」條件，並支援既有排序選項。
- 標籤篩選是獨立模式，不與關鍵字搜尋或狀態、優先級、日期等一般篩選條件組合。前端切換模式時負責清除另一模式的輸入與活躍狀態，排序設定則保留。
- 既有一般篩選仍可組合狀態、優先級與日期條件；標籤功能不得縮減原有行為。
- 新增與編輯任務的標籤欄位為可搜尋的多選 interface，選項頂端固定提供「新增標籤」。選取後才顯示名稱輸入，成功儲存任務後，新標籤自動成為該任務的已選項目。
- 任務卡片使用純文字 chip 顯示標籤並允許自動換行，不加入顏色或圖示。一般標籤 chip 可啟用該標籤篩選；「未加標籤」以灰色 chip 呈現並可啟用未加標籤篩選。
- 編輯表單中的已選 chip 提供移除控制；任務卡片上的 chip 不提供移除控制。
- UI 必須明確顯示目前的搜尋、一般篩選或標籤篩選模式，並在切換模式時移除上一模式的結果摘要。
- 所有使用者提供的標籤文字在輸出到 HTML 時都必須安全轉義。
- 第一版不新增獨立的標籤管理 module；標籤建立是任務寫入流程的一部分。

## Testing Decisions

- 好測試只驗證可觀察行為：HTTP 狀態、JSON 回應、後續讀取結果、資料是否整體成功或失敗，以及使用者在瀏覽器看見的互動結果；不得直接斷言 Controller 方法、ORM 關聯或中介表的內部實作步驟。
- 主要自動化 seam 是 Laravel JSON HTTP interface，使用 Feature tests、真實測試資料庫及 `RefreshDatabase`。同一 seam 涵蓋任務寫入、標籤選項、任務讀取及標籤篩選。
- 建立任務測試涵蓋：無標籤、選取既有標籤、建立一或多個新標籤、混用既有與新標籤，以及回應包含完整標籤集合。
- 更新任務測試涵蓋：新增標籤、移除部分標籤、移除全部標籤，以及未提供標籤資料的局部更新保留原關聯。
- 驗證測試涵蓋：空名稱、超過 50 個字元、頭尾空白、大小寫重複、正規化後重複，以及超過 10 個標籤。
- 原子性測試必須證明：任一新標籤或任務資料無效時，任務更新、標籤建立與關聯同步全部不生效。
- 唯一性測試必須證明顯示名稱只有大小寫或頭尾空白不同時不能建立第二筆標籤，且回傳指定錯誤而非自動套用既有標籤。
- 標籤選項測試涵蓋依名稱排序、名稱搜尋、未使用標籤仍存在，以及不回傳虛構的「未加標籤」資料列。
- 標籤篩選測試涵蓋單一標籤、未加標籤、全部、空結果，以及每種既有排序方式仍能正確運作。
- 回歸測試必須證明完整任務清單、關鍵字搜尋、一般組合篩選、完成、重新開啟及刪除任務仍維持原有外部行為。
- 既有的任務篩選與排序 Feature tests 是本功能的測試先例；新增測試應延續透過 HTTP JSON interface 驗證結果順序與回應結構的方式。
- 預設測試命令必須能發現並執行所有新增測試；若現有 testsuite 設定未涵蓋 Feature tests，實作時要一併修正測試探索設定。
- 專案目前沒有 JavaScript DOM 或瀏覽器自動化測試基礎，第一版不為此功能另加測試框架。UI 透過 `/todo` 的瀏覽器驗收清單確認：建立標籤、chip 顯示與換行、編輯移除、點擊篩選、模式互斥、排序保留及錯誤後保留表單內容。
- 不新增直接測試 Model 或中介關聯表的單元測試 seam；這些細節由較高的 HTTP interface 測試間接覆蓋。

## Out of Scope

- 標籤重新命名。
- 標籤刪除。
- 獨立標籤管理頁或管理面板。
- 標籤顏色、自訂圖示或視覺主題。
- 同時選擇多個標籤進行 AND 或 OR 篩選。
- 將標籤篩選與關鍵字搜尋或一般篩選條件組合。
- 熱門標籤、最近使用標籤或手動排序標籤。
- 為不同使用者建立個人標籤集合。
- 為此功能導入登入、授權或多租戶資料隔離。
- 為前端另行導入 JavaScript 單元測試或瀏覽器自動化框架。

## Further Notes

- 現有應用是單一共用 Todo List，後端提供 JSON HTTP interface，前端由 Blade 頁面中的 JavaScript 操作。實作必須維持現有任務流程相容。
- 「未加標籤」是零個標籤關聯所呈現的狀態，不是可建立、重新命名或刪除的標籤。
- 使用者先前提到未來希望能自行編輯與刪除標籤；這些能力刻意延後，待獨立標籤管理功能再處理其刪除影響與重新命名規則。
- 本功能沒有產出 prototype，也沒有需要引用的 prototype 決策片段。
- 目前沒有符合 ADR 條件的決策：採用多對多關係是標籤語意的直接結果，沒有額外且令人意外的架構取捨需要記錄。
